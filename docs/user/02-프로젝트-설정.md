# 02 프로젝트 설정

프로젝트는 TOML 파일 하나입니다(`examples/demo.toml` 참고). 관리자는 웹의 **프로젝트 편집** 화면에서도 같은 내용을 편집할 수 있습니다. 저장하면 서버가 먼저 검증하고, 통과하면 기존 파일을 `.toml.bak`으로 백업한 뒤 새 파일로 바꾸고 스캔을 다시 시작합니다. 검증에 실패하면 기존 설정이 그대로 유지됩니다.

모르는 항목 이름은 **오류로 거부**합니다(오타 방지).

## `[server]`

| 항목 | 기본 | 설명 |
|---|---|---|
| `listen` | `127.0.0.1:8080` | 수신 주소. 기본은 이 컴퓨터에서만 접속됩니다. 바꾸는 방법과 주의는 [03](03-운영과-보안.md)에 있습니다. 바꾼 값은 서버를 다시 시작해야 반영됩니다 |
| `publish_ms` | `100` | 변경된 값을 브라우저로 보내는 주기(ms). 최소 20 |

## `[[device]]` 장치 (여러 개 가능)

| 항목 | 기본 | 설명 |
|---|---|---|
| `name` | 필수 | 장치 이름(유일) |
| `driver` | 필수 | 지금은 `"modbus-tcp"`만 지원합니다 |
| `address` | 필수 | `호스트:포트` |
| `timeout_ms` | `500` | 연결·요청 제한 시간 |
| `scan_ms` | `100` | 스캔(읽기) 주기. 최소 10 ms, 제품 목표는 100 ms 이상입니다 |

## `[[tag]]` 태그

| 항목 | 기본 | 설명 |
|---|---|---|
| `name` | 필수 | 태그 이름(유일, 대소문자 구분). 점(`.`)으로 계층처럼 쓸 수 있습니다 |
| `device` | 필수 | 위 장치의 `name` |
| `unit` | `1` | MODBUS 유닛(국번) 번호 |
| `space` | 필수 | `coil`, `discrete`, `holding`, `input` |
| `address` | 필수 | 주소(0부터, 0~65535) |
| `type` | 필수 | `analog`(숫자) 또는 `digital`(켜짐/꺼짐) |
| `unit_text` | `""` | 단위 표시(`"%"`, `"°C"`) |
| `writable` | `false` | 쓰기 허용. 서버에서 쓰기를 켜야 실제로 쓸 수 있습니다([03](03-운영과-보안.md)) |
| `scale` | 아날로그 필수 | 환산 설정 |
| `alarm` | 없음 | 알람 설정 |

- 아날로그는 `holding` 또는 `input`, 디지털은 `coil` 또는 `discrete` 영역이어야 합니다.
- 값은 16비트 부호 없는 정수(0~65535)로 읽습니다.
- 영역 이름은 MODBUS 용어입니다: `coil`(코일, 읽기·쓰기 비트), `discrete`(이산 입력, 읽기 전용 비트), `holding`(보유 레지스터), `input`(입력 레지스터).

### 환산 `scale = { ... }`

장치의 원시 값을 사람이 읽는 값으로 바꿉니다.

| 항목 | 기본 | 설명 |
|---|---|---|
| `plc_base`, `plc_full` | 필수 | 장치 값의 하한·상한(예: 0, 4000) |
| `base`, `full` | 필수 | 표시 값의 하한·상한(예: 0, 100) |
| `profile` | `0` | 0 선형, 1 코사인, 3 구간 반전, 4 무변환 (그 밖의 값은 무변환) |
| `delay` | `0` | 1차 지연 계수(0~1000). 값이 클수록 천천히 따라갑니다 |
| `range` | `0` | 0 그대로, 1 표시 범위로 자르기, 2 표시 범위 밖이면 값을 버리고 이전 값 유지 |

선형 예: `plc 0~4000 → 표시 0~100`이면 원시 값 2000은 50으로 보입니다.

### 알람 `alarm = { kind = N, ... }`

한계 값(`hihi` 상상한, `high` 상한, `low` 하한, `lolo` 하하한)과 복귀 여유 `gap`을 씁니다. 값이 한계에 도달하면 알람이 기록되고, `한계 ∓ gap`을 벗어나면 복귀로 기록합니다.

| 종류 | 필요한 한계 | 뜻 |
|---|---|---|
| 0 | hihi, lolo | 상·하 극한 |
| 1 | hihi | 상 극한 |
| 2 | lolo | 하 극한 |
| 3 | high, low | 상·하 일반 |
| 4 | high | 상 일반 |
| 5 | low | 하 일반 |
| 6 | hihi, high, low, lolo | 4단계 |
| 7 | hihi, high | 상측 2단계 |
| 8 | lolo, low | 하측 2단계 |
| 9 | high, low | 범위 안(MIDDLE) 상태 전이 기록 |

디지털 태그의 알람은 `alarm = { kind = N }`(0~3)입니다: 종류 0은 켜지면 알람·꺼지면 복귀, 1은 꺼지면 알람·켜지면 복귀, 2는 꺼짐만 기록, 3은 켜짐만 기록합니다. 값이 **바뀔 때만** 기록합니다.

필요한 한계가 없으면 설정을 거부합니다.

## `[[screen]]`과 `[[screen.widget]]` 공정 화면

```toml
[[screen]]
name = "주 공정 화면"
width = 800
height = 360

[[screen.widget]]
id = "w-tank-1"
kind = "tank"          # value, gauge, tank, lamp, pump, valve, label
label = "원수 탱크 수위"
tag = "TANK_LEVEL"
x = 40.0
y = 40.0
width = 180.0
height = 220.0
min = 0.0
max = 100.0
```

관리자는 웹의 그래픽 편집 모드에서 10 px 격자에 맞춰 위젯을 끌어 놓고 태그를 연결할 수 있습니다. 위젯은 정해진 벡터 심볼만 지원하며 임의의 HTML이나 스크립트는 넣을 수 없습니다.

## 태그 가져오기

관리자는 `POST /api/v1/project/import`로 쉼표 텍스트 형식의 태그 목록을 가져올 수 있습니다(웹 화면은 아직 없습니다).
- `mode`: `preview`(기본, 보고서만 돌려주고 바꾸지 않음), `merge`, `replace`. **가져오기 전에 반드시 미리보기로 보고서를 확인하세요.** 보고서는 가져온 수, 이름이 바뀐 태그, 값이 바뀐 항목, 무시한 항목, 읽지 못한 항목을 줄 번호와 함께 알려 줍니다.
- 이름이 겹치면(대소문자 무시) 이름 끝의 숫자를 올려 새 이름을 정합니다.
- 기존 제품의 실제 프로젝트 파일을 직접 읽는 기능은 준비 중이며, 이 버전에서는 검증되지 않았습니다.

## 설정 검증 팁

- 서버를 시작하면 설정을 먼저 검증하고 문제가 있으면 줄 정보와 함께 이유를 알려 줍니다.
- 한 번에 장치·태그를 많이 만들 때는 먼저 시뮬레이터로 확인한 뒤 실제 장치에 연결하세요.
