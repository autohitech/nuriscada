# 03 운영과 보안

> 이 버전의 보안은 **설계 단계의 첫 구현**이며 외부 보안 검토나 인증을 받지 않았습니다. 인터넷에 직접 노출하지 마세요.

## 기본 동작 (안전한 쪽이 기본)

- 서버는 **이 컴퓨터(`127.0.0.1`)에서만** 접속을 받습니다.
- **기본 계정이 없습니다.** 처음에 `--init-admin <계정>`으로 관리자를 직접 만들어야 서버가 시작됩니다.
- **쓰기(제어)는 꺼져 있습니다.**
- 모든 화면과 API는 로그인이 필요합니다.

## 계정과 역할

| 역할 | 할 수 있는 일 |
|---|---|
| `viewer` 조회자 | 값·알람·이력·화면 보기 |
| `operator` 운전원 | 조회자 + 알람 확인(ACK), 쓰기(켠 경우) |
| `admin` 관리자 | 운전원 + 계정 추가, 감사 기록 조회, 프로젝트 편집·가져오기 |

- 비밀번호는 12~128바이트이고 Argon2id로 해시해 저장합니다. 계정 이름은 영문·숫자·밑줄·하이픈·점 1~64자입니다.
- 세션은 8시간 뒤 만료되고 사용자당 가장 최근 세션 하나만 유지합니다. 로그인 시도는 서비스 전체에서 60초에 10회로 제한합니다.
- **아직 없는 것**: 비밀번호 변경·계정 비활성화(웹에서), 화면·태그별 세부 권한, 외부 인증(OIDC/LDAP). 필요하면 관리자 계정을 새로 만들고 데이터 폴더를 관리하세요.

자동화에서 비밀번호를 줄 때는 명령행 인자 대신 표준 입력을 쓰세요.

```sh
printf '%s\n' "$PASSWORD" | bin/nuriscada-server --config my.toml --init-admin admin --password-stdin
```

## 쓰기(제어) 켜기

쓰기는 아래를 **모두** 만족할 때만 됩니다.

1. 서버를 `--enable-writes`로 시작했고,
2. 서버가 루프백(`127.0.0.1`)에서만 수신하고,
3. 요청이 이 컴퓨터에서 왔고,
4. 그 태그가 `writable = true`이고,
5. 로그인한 사용자가 `operator` 또는 `admin`입니다.

```sh
bin/nuriscada-server --config my.toml --enable-writes
```

- 코일은 켜짐/꺼짐, 레지스터는 **환산 전 원시 정수(0~65535)**를 씁니다. 역환산은 하지 않습니다.
- 통신 품질이 나쁜 태그에는 쓰지 않습니다.
- 화면에서 대상과 값을 확인한 뒤 별도 버튼으로 전송합니다. 장치가 응답하지 않으면 **자동으로 다시 보내지 않습니다**(이미 써졌을 수 있기 때문입니다). 결과는 다음 정상 스캔 값으로 확인하세요.
- 쓰기 요청은 장치로 보내기 **전에** 감사 기록에 먼저 남기고, 저장에 실패하면 보내지 않습니다.
- 기능은 MODBUS 단일 코일(05)·단일 레지스터(06) 쓰기뿐입니다.

## 다른 컴퓨터에서 접속하기 (LAN·원격)

> 현재는 **HTTPS 역방향 프록시를 앞에 두는 구성만** 의도합니다. 서버 자체는 TLS를 처리하지 않습니다. 프록시를 통한 구성은 **충분히 시험하지 않았습니다.**

- 루프백이 아닌 주소(`--listen 0.0.0.0:8080` 등)로 수신하려면 `--allow-external`이 필요합니다. 이때 서버는 **읽기 전용**으로 동작합니다(쓰기·계정 변경 거부). 쓰기를 켠 서버는 루프백에서만 시작됩니다.
- 비루프백 접속의 세션 쿠키에는 `Secure`가 붙으므로 **HTTPS가 아니면 로그인이 유지되지 않습니다.**
- 인터넷에 공개하려면 `--public-read-only`와 HTTPS 프록시(예: Caddy, nginx)가 필요합니다. 공개 인스턴스는 **조회 전용**으로 두고, 제어가 필요한 서버는 별도로 두어 VPN이나 내부망에서만 쓰세요.
- 공개 프록시를 쓰기 가능한 서버에 연결하지 마세요.

## 데이터와 백업

- 계정·세션·감사·알람·이력은 **`.nuriscada/operations.sqlite3`**(설정 파일 옆, `--data-dir`로 변경)에 저장합니다. Unix에서는 폴더 권한이 `0700`이어야 합니다. Windows에서는 설치 폴더의 접근 권한을 직접 제한하세요.
- 프로젝트마다 별도 데이터 폴더를 쓰세요. `--data-dir`을 바꾸면 `--init-admin`과 실행에 **같은 경로**를 주어야 합니다.
- **백업은 서버를 멈춘 뒤** 설정 파일과 `.nuriscada` 폴더 전체를 복사하세요(데이터베이스가 쓰기 로그 파일을 함께 쓰므로 실행 중 복사는 일관성을 보장하지 않습니다). 온라인 백업과 마이그레이션 도구는 아직 없습니다.
- 프로젝트를 웹에서 저장하면 직전 설정이 `*.toml.bak`으로 남습니다.
- 태그 이력은 태그당 최신 10,000개 표본을 유지하고 오래된 것은 자동으로 지웁니다.

## 감사 기록

로그인 성공·실패, 로그아웃, 계정 생성, 프로젝트 변경·가져오기, 쓰기 요청·거부·결과, 알람 확인을 기록하고 관리자가 조회합니다. 비밀번호와 세션 토큰은 기록하지 않습니다. 기록은 해시 체인으로 이어져 변조를 알아챌 수 있게 했지만, 데이터베이스 관리자가 전체를 다시 쓰면 외부 기준 없이는 알아낼 수 없습니다. 외부 서명·원격 보관은 후속입니다.

## 알람과 이력의 한계

- 알람 기록은 200 ms마다 저장합니다. **비정상 종료 직전 약 0.2초의 기록은 잃을 수 있습니다.**
- 이력은 무손실이 아니며 디스크 장애 복구나 장기 보관 기능은 없습니다.
- 알람 확인(ACK)과 정상 복귀는 별개입니다.

## 보안 점검표 (운영자용)

- [ ] 관리자 비밀번호를 길고 고유하게 만들었다.
- [ ] 서버를 루프백이나 신뢰하는 내부망에서만 열었다.
- [ ] 쓰기가 필요 없으면 `--enable-writes`를 쓰지 않았다.
- [ ] 외부 접속은 HTTPS 프록시 뒤에 두고 조회 전용으로 구성했다.
- [ ] 데이터 폴더와 백업 접근을 제한했다.
- [ ] 안전 기능은 독립된 하드웨어 장치로 구현했다([안전 고지](../../SAFETY.md)).
