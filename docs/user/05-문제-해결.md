# 05 문제 해결

서버가 출력하는 메시지와 해결 방법입니다.

| 메시지(일부) | 원인과 해결 |
|---|---|
| `먼저 같은 설정·데이터 경로로 --init-admin <계정>을 실행하라` | 관리자가 아직 없습니다. `bin/nuriscada-server --config 설정.toml --init-admin admin`을 한 번 실행하세요. 다른 `--data-dir`을 썼다면 같은 경로를 주세요 |
| `설정 파일을 읽을 수 없다` | `--config` 경로가 틀렸습니다 |
| `설정 오류: ...` / `설정 형식 오류: ...` | TOML 문법이나 값이 잘못되었습니다. 메시지의 태그·장치 이름을 확인하세요([02](02-프로젝트-설정.md)). 모르는 항목 이름도 오류입니다 |
| `데이터 디렉터리는 소유자만 접근할 수 있어야 한다 (0700)` | 데이터 폴더 권한이 넓습니다(macOS/Linux). `chmod 700 .nuriscada` |
| `루프백이 아닌 주소(...)에서 수신하려면 --allow-external이 필요하다` | 외부 수신은 명시해야 합니다. [03](03-운영과-보안.md)의 외부 접속 절을 먼저 읽으세요 |
| `쓰기 활성화는 루프백 바인딩에서만 가능하다` | `--enable-writes`는 `127.0.0.1`에서만 됩니다 |
| `바인딩하지 못했다` | 포트가 이미 쓰이는 중입니다. `--listen 127.0.0.1:8081`처럼 바꾸세요 |
| `데이터 디렉터리는 웹 자원 디렉터리 밖에 있어야 한다` | `--web-dir` 안에 데이터를 두지 마세요 |
| `운영 저장소 열기 실패` | 데이터 파일을 다른 서버가 쓰고 있거나 권한 문제입니다 |

## 증상별

- **브라우저에 화면이 안 뜨고 API 텍스트만 나온다**: 웹 화면 폴더를 못 찾았습니다. 서버가 `웹 화면: http://...` 줄을 출력하는지 보고, 묶음의 `web/` 폴더를 옮기지 않았는지 확인하세요. 직접 지정하려면 `--web-dir <경로>`.
- **로그인이 계속 풀린다**: 비루프백 주소로 접속하면 쿠키에 `Secure`가 붙어 HTTPS가 아니면 유지되지 않습니다. `http://127.0.0.1:8080/`로 접속하거나 HTTPS 프록시를 두세요.
- **태그가 "통신 불량"으로 나온다**: 장치에 닿지 않았거나 응답이 늦습니다. 장치 주소·포트·방화벽을 확인하고 `timeout_ms`를 늘려 보세요. 상태 줄과 `GET /api/v1/status`의 `last_error`에 마지막 오류가 있습니다. 통신 불량인 동안에도 마지막 값은 남아 있습니다.
- **값이 이상하게 크거나 작다**: `scale`의 `plc_base/plc_full`이 장치가 실제로 보내는 값 범위와 맞는지 확인하세요. 원시 값은 0~65535 정수로 읽습니다.
- **알람이 안 뜬다**: 종류에 필요한 한계가 모두 있는지, `gap`이 너무 크지 않은지 확인하세요. 한계에 **도달**(`≥`/`≤`)해야 합니다.
- **쓰기 버튼이 없거나 거부된다**: [03](03-운영과-보안.md)의 다섯 조건을 모두 확인하세요(서버 `--enable-writes`, 루프백, 태그 `writable`, 역할, 통신 품질).
- **macOS "확인되지 않은 개발자" / Windows SmartScreen**: [01](01-시작하기.md)의 서명 안내를 보세요.

## 도움 받기

- 재현 방법, 버전(`bin/nuriscada-server --version`), 운영체제, 메시지를 적어 저장소 이슈로 알려 주세요. **비밀번호·세션·내부 주소가 든 파일은 올리지 마세요.**
- 보안 문제는 공개 이슈 대신 [보안 정책](../../SECURITY.md)의 비공개 신고를 쓰세요.
