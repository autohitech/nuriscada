# 0008. 보안 신고·대응·지원 버전 정책

- 상태: 확정 (2026-10-18, 출처: 사용자). 세부 기준 일부는 첫 릴리스 전에 정한다.
- 결정:

| 항목 | 결정 |
|---|---|
| 신고 채널 | GitHub 비공개 보안 신고(Security Advisories) |
| 접수 확인 | 7일 이내 (목표) |
| 수정 목표 | 90일 이내 (목표) |
| 지원 버전 | 최신 주 버전의 최신 마이너 라인과 직전 마이너 라인. 1.0 이전에는 가장 최근 릴리스만 |
| 공개 방식 | 수정 배포 후 Security Advisory 공개, 필요 시 CVE 신청. 공개 시점은 신고자와 조율 |

- 의미: 위 기간은 보증이 아니라 노력 목표다. 책임 부인은 [0001](0001-license-apache-2.0.md)과 [SAFETY.md](../../SAFETY.md)를 따른다.
- 실행 조건:
  - 저장소에서 Private vulnerability reporting 기능을 켠다 (공개 전환 때 확인, 조건 4 [0007](0007-repository-release-and-ownership.md)).
  - 신고를 받을 담당자(최소 2명)와 대리 규칙을 정한다 [U].
  - 의존성 취약점 점검을 CI에 넣는다 ([정책](../requirements/dependency-license-policy.md) §6).
- 남은 결정: 심각도 분류(예: CVSS)와 심각도별 수정 목표, 담당자 지정, 기능별 지원 중단 공지 방식 [U].
