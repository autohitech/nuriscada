# 0005. 성능·용량 목표

- 상태: 확정 (2026-10-18, 출처: 사용자). 측정 방법과 기준 하드웨어는 제안이며 첫 구현 전에 확정한다.
- 결정:

| 항목 | 1단계 목표 |
|---|---|
| 태그 규모 | 한 프로젝트 약 **10,000개** |
| 최소 스캔 주기 | **100 ms** |
| 동시 브라우저 클라이언트 | 약 **50명** |
| 스캔 지터 | 실제 주기의 **20% 이내**, 소프트 실시간 |

- 의미:
  - 이 소프트웨어는 **감시·알람 중심 SCADA**다. 지터 목표는 범용 OS에서 달성 가능한 수준이며 **경성 실시간 제어 루프는 지원 목표가 아니다**. 제어가 필요한 곳은 PLC가 맡는다.
  - 100 ms는 "지원하는 가장 짧은 주기"다. 모든 태그가 항상 100 ms로 갱신된다는 뜻이 아니다. 장치 응답 속도와 통신 방식이 실제 갱신 속도를 정한다.
  - 약 10,000개와 50명은 한 호스트(코어 + 웹 서버)에서 함께 달성해야 하는 목표다.
- 측정 방법 [제안]:
  - **지터**: 스캔 주기의 설정값 대비 실제 간격의 99번째 백분위수와 최댓값을 기록한다. 합격은 99번째 백분위수가 설정값의 ±20% 이내다.
  - **용량**: 시뮬레이션 장치로 10,000 태그를 100 ms 주기 구성(장치 수와 블록 크기는 시험 계획에서 정한다)으로 운전하고, 50개 브라우저 클라이언트가 대표 화면을 보는 상태에서 측정한다.
  - **안정성**: 위 부하로 72시간 연속 운전하며 메모리와 핸들 수가 늘지 않아야 한다.
  - **기준 하드웨어**: 아직 정하지 않았다 [U]. 보통의 산업용 PC급(예: 4코어, 8 GB)을 후보로 두고 확정한다.
- OD-1 재검토 기준: 첫 수직 조각 구현에서 **위 목표를 기준 하드웨어에서 만족하지 못하고**, 원인이 언어·런타임 선택에 있다고 확인되면 기술 스택 결정([0002](0002-tech-stack-rust-core-web-ui.md))을 다시 연다. 개발 속도가 일정을 지연시키는 경우의 판단 기준은 별도로 정한다 [U].
- 요구사항 반영: SQ-R01, SQ-R03, SQ-R05.
- 남은 결정: 이력 저장 규모(초당 저장량, 보존 기간)와 알람 이벤트 처리량은 정하지 않았다 [U].
