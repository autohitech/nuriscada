# 0016. 쓰기 큐 정책 확정

- 상태: 확정 (2026-11-06, 출처: 사용자). 설계 [0007](../design/0007-write-queue.md)의 확인 3건을 아래와 같이 닫는다.
- 맥락: 단일 쓰기 직렬화·묶음 쓰기 API(#46)·감사 기록은 구현됐다. 인터록 요구사항과 기존 명령 0·100의 의미는 정해지지 않았다.

## 결정

- **재시도 없음(현행 유지).** 요청 전송 후 응답 유실·시간 초과는 자동 재시도하지 않는다(이중 동작 방지). 연결 실패 등 전송 전 실패도 재시도하지 않고 오류로 돌려준다. 이유: 쓰기는 멱등하지 않아 재전송이 장치를 두 번 움직일 수 있다.
- **묶음은 합치지 않는다(현행 유지).** 배치에 같은 태그가 두 번 나오면 순서대로 두 번 쓴다. last-wins 병합은 하지 않는다(설계 0007 §3 제안 기각). 이유: 요청 순서대로의 실행이 감사와 결과가 일대일로 맞고 예측 가능하다.
- **묶음 전송은 비원자적(구현됨, #46).** MODBUS 같은 장치·유닛의 연속 주소는 15·16으로 한 번에 보내고, 나머지는 단일 쓰기로 보낸다. 항목별 결과를 돌려주고 전체 성공 여부를 함께 준다.
- **인터록은 보류.** 태그별 쓰기 허용 조건식의 요구사항 정의가 먼저다. 정의되면 별도 설계로 다룬다.
- **기존 명령 0·100 매핑은 보류.** 참조 저장소의 정적 관측만으로는 의미를 확정할 수 없어 매핑하지 않는다. command 1≈단일·command 2≈배치 대응만 유지한다.
