# 0012. 구현 코드는 이 저장소에서 직접 개발한다

- 상태: 확정 (2026-10-18, 출처: 사용자)
- 결정: 구현 코드와 문서는 **이 저장소(`nuriscada`)에서 직접 개발**한다. 이전의 "다른 저장소에서 준비한 최종본만 올림" 방식은 이 시점부로 끝낸다.
- 이유: 코드는 커밋 이력, CI, 리뷰가 중요하다. 이 저장소에는 기존 제품의 분석 자료가 없어 직접 개발해도 오염 위험이 낮다.
- 규칙:
  - 기존 제품의 코드·디컴파일 결과·원본 자산·분석 문서를 이 저장소에 가져오지 않는다. 비공개 분석 자료에서 온 **동작 규칙은 명세 문서와 기대값 데이터**로만 들어온다.
  - 기대값 데이터(`tests/fixtures/expected/`)를 갱신할 때는 출처가 분석 자료임을 PR 본문에 적는다.
  - 기존 제품의 이름과 내부 식별자를 쓰지 않는다. 기여자와 에이전트는 이를 PR 점검 항목으로 확인한다.
  - 변경은 브랜치와 PR(스쿼시 병합)로 올린다 ([0009](0009-github-operations.md)). 저장소 초기 설정(이 결정 직후의 첫 골격)은 예외로 `main`에 바로 커밋했다.
- 영향: 설계 0001의 D-1이 해소된다. 공개 전환 조건 5번(이력에 기존 제품 흔적 없음)은 PR 점검과 정기 검색으로 유지한다.
