# 0009. GitHub 운영 설정

- 상태: 확정 (2026-10-18, 출처: 사용자)
- 결정:

| 항목 | 결정 |
|---|---|
| PR 병합 방식 | **스쿼시 병합만** 허용. 병합 커밋과 리베이스 병합은 끈다 |
| 병합 후 브랜치 | **자동 삭제** |
| `main` 브랜치 보호 | **보호 없음** (사용자 선택) |
| 접근 권한 | 핵심 멤버만 쓰기 권한, 외부 기여자는 포크 + PR |

- 적용 상태: 스쿼시만 허용과 자동 삭제는 저장소 `autohitech/nuriscada`에 적용했다(2026-10-18). 스쿼시 커밋의 제목은 PR 제목, 본문은 PR 본문을 쓴다.
- 보호 없음의 의미와 위험: 쓰기 권한이 있는 멤버는 `main`에 직접 push하거나 강제 push할 수 있다. 기록이 의도치 않게 바뀌거나 CI·DCO 검사를 건너뛴 변경이 들어갈 수 있다. 완화책:
  - 규약으로 PR을 쓰고 직접 push를 하지 않는다 ([CONTRIBUTING](../../CONTRIBUTING.md)).
  - 쓰기 권한자를 최소로 유지한다.
  - 외부 기여가 시작되거나 쓰기 권한자가 늘면 이 결정을 다시 연다 (PR 필수 + CI 통과 권장). 비공개 저장소는 현재 플랜에서 브랜치 보호 기능을 쓸 수 없고 공개 전환 뒤 가능하다.
- 비공개 동안의 작업 방식: 최종본은 분석 저장소의 준비 영역에서 만들고 검사한 뒤 올린다 ([0007](0007-repository-release-and-ownership.md)).
- 미정 [U]: 라벨 세트, 이슈 템플릿, 쓰기 권한자 명단, 비공개 취약점 신고 기능 활성화 시점(공개 전환 조건 4).
