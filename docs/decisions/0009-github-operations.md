# 0009. GitHub 운영 설정

- 상태: 확정. **2026-10-18에 `main` 보호 항목을 갱신했다**(처음 결정은 "보호 없음"). 출처: 사용자.
- 결정:

| 항목 | 결정 |
|---|---|
| PR 병합 방식 | **스쿼시 병합만** 허용. 병합 커밋과 리베이스 병합은 끈다 |
| 병합 후 브랜치 | **자동 삭제** |
| `main` 브랜치 보호 | **켬**(아래 설정). 직접 push와 강제 push, 브랜치 삭제를 막고 PR과 CI 통과를 요구한다 |
| 접근 권한 | 핵심 멤버만 쓰기 권한, 외부 기여자는 포크 + PR |

## `main` 보호 설정 (2026-10-18 적용)

| 설정 | 값 | 이유 |
|---|---|---|
| 병합 전 풀 리퀘스트 필수 | 켬. **승인 필수 수는 0** | 메인테이너가 한 명인 동안 본인 PR을 병합할 수 있게 한다. 변경이 항상 PR과 CI를 거치게 하는 것이 목적이다 |
| 상태 검사 통과 필수 | 켬: `rust (ubuntu-latest)`, `rust (macos-latest)`, `rust (windows-latest)`, `web (node)`, `의존성 라이선스·취약점 검사` | 세 OS 빌드·시험, 웹 검사, 의존성 라이선스·취약점 검사를 건너뛰지 못하게 한다 |
| 브랜치를 최신으로 유지 요구(strict) | 끔 | 병합 때마다 다시 얹는 수고를 줄인다. 충돌은 CI가 잡는다 |
| 관리자에게도 적용 | 켬 | 소유자도 직접 push할 수 없다. 긴급 시에는 보호를 잠시 끄고 이유를 기록한다 |
| 강제 push 금지, 삭제 금지 | 켬 | 이력이 의도치 않게 바뀌거나 사라지지 않게 한다 |
| 대화 해결·서명 커밋 필수 | 끔 | 기여자 규모가 작은 동안 부담이 크다. DCO 서명은 규약으로 요구한다([CONTRIBUTING](../../CONTRIBUTING.md)) |

- 적용 상태: 스쿼시만 허용과 자동 삭제, `main` 보호를 저장소 `autohitech/nuriscada`에 적용했다. 스쿼시 커밋의 제목은 PR 제목, 본문은 PR 본문을 쓴다.
- 이전 결정과의 관계: 비공개 저장소는 무료 플랜에서 브랜치 보호를 쓸 수 없어 처음에는 "보호 없음"으로 정했다. 저장소가 공개되어 쓸 수 있게 되었고 외부 기여를 받을 준비를 하므로 켰다.
- 운영 규칙:
  - 모든 변경은 브랜치 → PR → CI 통과 → 스쿼시 병합으로 한다. 태그 푸시는 보호 대상이 아니다(릴리스 절차는 [릴리스](../release.md)).
  - **쓰기 권한자가 둘 이상이 되거나 외부 기여가 시작되면** 승인 필수 수를 1로 올리고 DCO 검사를 필수 검사로 넣는 것을 검토한다.
  - 검사 이름(작업 이름)을 바꾸면 이 설정의 필수 검사 목록도 함께 바꿔야 한다. 이름이 맞지 않으면 PR이 영원히 병합되지 못한다.
  - 보호를 끄거나 바꿀 때는 이 문서에 날짜와 이유를 적는다.
- 위험과 한계: 관리자도 막히므로 CI가 장애일 때 병합이 멈출 수 있다(그때는 보호를 일시 해제). 메인테이너가 한 명이라 리뷰는 요구하지 않는다. 즉 **사람의 검토 없이 병합될 수 있다.**
- 비공개 동안의 작업 방식(이전 기록): 최종본은 분석 저장소의 준비 영역에서 만들고 검사한 뒤 올렸다([0007](0007-repository-release-and-ownership.md), 이후 [0012](0012-development-location.md)로 직접 개발로 바뀜).
- 미정 [U]: 라벨 세트, 이슈 템플릿, 쓰기 권한자 명단.
