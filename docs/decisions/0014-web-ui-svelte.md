# 0014. 웹 UI 프레임워크는 Svelte 5

- 상태: 확정 (2026-10-18, 출처: 사용자)
- 결정: 웹 UI는 **Svelte 5 + TypeScript + Vite**(SvelteKit 없이 정적 번들)로 만든다.
- 이유: [설계 0002](../design/0002-web-ui-framework.md)의 비교에서 고빈도 갱신에 유리하고 번들이 작아 오프라인 패키지에 부담이 적으며 접근성 부품이 있기 때문이다.
- 위험과 대응:
  | 위험 | 대응 |
  |---|---|
  | 그래픽 편집기용 대형 부품(속성 표, 도킹 레이아웃, 드래그)의 생태계가 React보다 작다 | 필요한 부품은 프레임워크 중립 라이브러리나 직접 구현으로 채운다. 편집기 조각 시작 전에 부품 목록을 점검한다 |
  | 1만 태그 렌더링 성능을 측정하지 않았다 | 목록은 가상 스크롤(보이는 행만 그림)로 만들었다. S5에서 1만 태그·100 ms 갱신 부하로 측정하고, 기준 미달이면 이 결정을 다시 연다 |
  | `svelte-check`가 아직 TypeScript 7을 지원하지 않는다 | TypeScript 6을 쓴다. 지원이 나오면 올린다 |
- 구성: `web/`에 Vite 프로젝트. 상태는 한 저장소 객체(`store.svelte.ts`)에 두고 태그 칸 단위로 갱신해 값이 바뀐 행만 다시 그린다. 디자인 토큰은 CSS 변수(`styles/tokens.css`)로 두어 프레임워크와 독립이다.
- 영향: 서버가 `web/dist`를 같은 출처에서 정적으로 제공한다(외부 CDN 없음). npm 의존성은 허용 라이선스만 쓰며 CI에서 검사한다 (`web/scripts/check-licenses.mjs`).
