# 0002. 기술 스택: Rust 코어·드라이버 + 웹 UI

- 상태: 확정 (2026-10-18, 출처: 사용자). 수직 조각 비교는 하지 않고 바로 정했다.
- 맥락: Windows·Linux·macOS와 x86-64·arm64를 지원하고, 장치 드라이버를 공개 규격에서 새로 작성하며, 소스를 공개하는 SCADA. 개발에 바로 쓸 수 있는 언어 경험은 Rust, TypeScript(웹 프론트엔드), 그 밖의 언어(Go·C++·Java 등)다.
- 결정:
  - **코어, 스캔·쓰기 큐, 드라이버, 서버는 Rust**로 작성한다.
  - **UI는 웹 기술(TypeScript)**로 만든다. 편집기와 런타임 화면은 브라우저에서 동작한다.
- 이유:
  - 프로토콜 파서와 상시 운전 프로세스에서 메모리 안전과 예측 가능한 지연이 중요하다 [I].
  - 단일 실행 파일에 가까운 배포와 세 OS·두 CPU 교차 컴파일이 쉽다 [I].
  - 팀이 두 언어에 경험이 있다.
  - 그래픽 오브젝트 약 120종은 웹 캔버스/SVG 생태계 위에서 한 번만 구현한다.
- 알려진 위험과 대응:
  | 위험 | 대응 |
  |---|---|
  | 개발 속도와 Rust 학습 비용 | 첫 구현을 작은 수직 조각(값 환산·알람·MODBUS TCP 읽기·최소 화면)으로 시작한다 |
  | GUI를 웹으로 둘 때 로컬 시리얼 접근 | 장치 접근은 항상 Rust 코어가 맡고 UI는 코어의 API만 쓴다 |
  | 코어와 UI의 계약 | 계약(API)을 문서로 먼저 정하고, 타입을 한 곳에서 생성해 두 언어가 공유한다 |
  | 실시간 렌더링 성능 | 변경된 오브젝트만 다시 그린다. 성능 목표는 OD-4에서 정한다 |
  | 비교 없이 결정함 | 수직 조각 구현에서 요구한 성능·개발 속도를 만족하지 못하면 이 결정을 다시 연다. 재검토 기준은 [0005](0005-performance-targets.md)에 적었다 |
- 결과: 의존성은 [정책](../requirements/dependency-license-policy.md)에 따라 허용 등급만 쓴다. Rust 쪽은 `cargo-deny`, 웹 쪽은 라이선스 검사기로 CI에서 검사한다.
- 남은 결정: UI를 브라우저만으로 할지 데스크톱 셸을 더할지(OD-2), 디자인 방향(OD-3), 용량·지터 목표는 [0005](0005-performance-targets.md)로 정했다.
