# 0006. 표준 적용 수준과 보안 정책

- 상태: 확정 (2026-10-18, 출처: 사용자). 세부 구현은 설계 단계에서 정한다.
- 결정:

| 항목 | 결정 |
|---|---|
| 표준 적용 | HMI 설계(ISA-101 계열), 알람 관리(ISA-18.2 계열), 산업 제어 보안(IEC 62443 계열)은 **설계 참고 지침**으로 따른다. **인증은 목표가 아니다.** 표준을 준수한다거나 인증받았다고 표기하지 않는다 |
| 인터넷 공개 | **읽기 전용만 지원**한다. 제어(쓰기)는 LAN 또는 VPN 내부 접속에서만 활성화할 수 있다 |
| 인증 | **로컬 계정**을 기본으로 하고, 환경에 따라 **외부 인증(OIDC, LDAP)을 선택적으로 연동**한다. 외부 서비스 없이도 동작해야 한다(오프라인 설치 보장) |
| 감사 기록 | **모든 쓰기, 설정 변경, 로그인(성공·실패)**을 기록한다. 전자서명과 2인 승인은 이번 범위에 넣지 않는다 |

- 구체화 원칙:
  - **읽기 전용 공개 모드**: 인터넷에서 접근 가능한 구성에서는 쓰기·설정 변경 API를 서버가 거부한다. 화면에서 숨기는 것만으로 충족하지 않는다. 쓰기 허용은 접속 경로(내부 인터페이스/VPN)와 관리자 설정이 모두 맞을 때만 켜진다. 판정 방식(수신 인터페이스, 신뢰 프록시 헤더 등)은 설계 때 정하며 위조 가능한 입력에 의존하지 않는다.
  - **계정**: 기본 계정·기본 비밀번호 없음, 최초 실행 시 관리자 설정, 비밀번호는 느린 해시(예: Argon2id)로 저장, 로그인 시도 속도 제한, 세션 만료. 역할 기반 권한(화면·조작 단위).
  - **감사 기록**: 사용자, 시각, 대상(태그/설정), 이전 값과 새 값, 접속 출처를 남긴다. 일반 사용자가 지울 수 없고 변조를 발견할 수 있는 형태(예: 순서 번호와 체인 해시)로 보관한다. 보존 기간은 정하지 않았다 [U].
  - **표준의 사용**: 요구사항 문서에서 표준을 참조한 항목은 "참고"로 표기한다. 표준과 다르게 설계한 부분은 이유를 기록한다.
- 이유: 무료 오픈소스 프로젝트에서 인증 비용을 지지 않으면서 권장 관행의 품질 이점을 얻는다. 인터넷에 노출된 인스턴스에서 설비 제어를 막아 가장 큰 위험을 줄인다.
- 영향: 결정 [0003](0003-ui-delivery-browser-first.md)의 시나리오 ③은 읽기 전용으로 한정된다. 요구사항 SQ-S01, S03, S07, A03, U04에 반영했다.
- 남은 결정: 감사 기록의 보존 기간, 외부 인증 지원 범위(OIDC만 / LDAP 포함), 다중 인증(MFA) 지원 여부 [U].
