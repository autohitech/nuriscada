# 0003. UI 제공 형태: 브라우저 UI 우선, 데스크톱 셸은 나중에

- 상태: 확정 (2026-10-18, 출처: 사용자)
- 결정:
  - UI는 **브라우저에서 동작하는 웹 UI**로 제공한다. 데스크톱 셸(Tauri 등)은 1단계에 넣지 않고, 설치형 요구가 확인되면 추가한다.
  - 1단계에서 지원할 접속 시나리오는 네 가지다: ① 같은 장치에서 로컬 실행, ② LAN·웹을 통한 원격 브라우저 접속, ③ 인터넷에 공개된 서비스(클라우드/원격 관제), ④ 인터넷 없는 오프라인 설치.
- 이유: 코어가 서버로 동작하고 한 코드로 로컬·원격·게시를 모두 다룰 수 있다. 셸은 같은 웹 UI를 감싸는 것이어서 나중에 더해도 재작업이 작다 [I].
- 결과와 설계 제약:

| 시나리오 | 설계 제약 |
|---|---|
| ① 로컬 | 기본 바인딩은 루프백(`127.0.0.1`)이다. 외부 노출은 명시적 설정으로만 켠다 |
| ② LAN·웹 원격 | 인증·권한·TLS가 필수다. 기본 계정·기본 비밀번호를 두지 않는다. 최초 실행 시 관리자 설정을 강제한다 |
| ③ 인터넷 공개 | ②의 조건에 더해 속도 제한, 감사 로그, 취약점 대응 절차가 필요하다. **읽기 전용만 지원**한다([0006](0006-standards-security-policy.md)). 제어(쓰기)는 LAN·VPN 내부에서만 활성화하며, 역방향 프록시나 VPN 뒤 배치를 권장 구성으로 문서화한다. 보안 검토 전에는 "지원"이라고 표기하지 않는다 |
| ④ 오프라인 | 웹 자산(스크립트, 글꼴, 아이콘, 지도 타일 등)을 모두 설치 패키지에 포함한다. 외부 CDN, 외부 글꼴, 온라인 라이선스 확인에 의존하지 않는다 |

- 인터넷 공개의 범위와 보안 정책은 [0006](0006-standards-security-policy.md)에서 확정했다.
