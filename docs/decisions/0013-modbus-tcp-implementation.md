# 0013. MODBUS TCP 드라이버는 직접 구현한다

- 상태: 확정 (2026-10-18). 첫 수직 조각 S2에서 평가해 정했다. 외부 크레이트와의 비교는 문서와 의존성 구성 기준이며 성능 비교 시험은 하지 않았다.
- 결정: MODBUS TCP 마스터(읽기 기능 01~04)를 외부 MODBUS 크레이트 없이 직접 구현한다. 비동기 입출력은 `tokio`만 쓴다.
- 이유:
  - 읽기 프로토콜은 작다: 7바이트 머리와 5바이트 요청, 기능·바이트 수 검증이 전부다. 프레임 부호화·해석을 I/O 없는 순수 함수로 두어 공개 규격의 예제 프레임으로 직접 시험한다.
  - 시간 제한, 재연결, 연결 상태 진단, 오류 분류(`Timeout`/`Connection`/`Protocol`/`Device`)를 드라이버 인터페이스에 맞춰 직접 통제할 수 있다.
  - 의존성이 `tokio`(와 그 하위 의존성)뿐이라 라이선스·취약점 검사 범위가 작다.
- 위험과 완화: 기능 코드 5·6·15·16(쓰기)과 비표준 장치의 변종은 아직 구현하지 않았다. 쓰기 조각에서 같은 구조로 확장하고, 장치별 차이는 시뮬레이터에 재현해 시험한다. 직접 구현한 프레임 처리의 결함 위험은 순수 함수 단위 시험과 시뮬레이터 통합 시험(시간 초과, 연결 끊김, 오류 응답, 거래 식별자 불일치)으로 줄인다.
- 영향: 설계 0001의 D-5가 해소된다. 드라이버 인터페이스의 읽기 단위는 `ReadBlock`(유닛, 영역 번호, 시작 주소, 개수, 데이터 종류) 하나로 정했다.
