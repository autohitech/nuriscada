# 0010. 동작 기준선: 관측 없이 예측으로 진행

- 상태: 확정 (2026-10-18, 출처: 사용자)
- 결정:
  - 기존 제품을 실행해 얻는 **관측 기준선은 만들지 않고**, 정적 분석에서 도출한 **예측 기준선**으로 진행한다.
  - 기대값 JSON만 데이터로 NuriScada에 이식한다 ([`tests/fixtures/expected/`](../../tests/fixtures/expected/README.md)). 예측기 코드는 이식하지 않고, 이를 읽는 시험 코드는 Rust로 새로 작성한다.
- 의미와 한계:
  - NuriScada는 기존 제품과 **동작이 동일하다고 주장하지 않는다.** 예측과 일치하는지만 검증하며, 이는 기존 제품과의 동등성을 증명하지 않는다.
  - 파일 형식 읽기 호환(`Local.tagx`, `SCAN.NNN` 등)도 실제 기존 제품이 만든 파일로 검증하지 않았다. 호환 범위는 "분석에 기반한 최선의 노력"으로 표기한다.
  - 예측이 틀렸을 가능성은 남는다. 분석 중 예측이 틀려 정정한 사례가 있었다(호스트의 필드 읽기 규칙). 예측 기준선의 신뢰도는 관측 기준선보다 낮다.
- 재개 조건 (관측을 다시 시도하는 경우, 사용자가 정하면 열린다):
  - 격리된 Windows 환경(가상 머신 또는 별도 PC)을 확보한다.
  - 사용자가 합법적으로 가진 평가/데모 범위 안에서만 실행한다. 라이선스 확인을 우회하지 않는다.
  - 샘플 프로젝트는 사양서대로 기존 제품의 편집기에서 직접 만든다 (사용자 선택).
  - 관측이 생기면 같은 사례 이름으로 예측과 대조하고, 다르면 관측을 따라 기대값 파일을 고친다.
- 이유: 환경 구성과 라이선스 제약으로 관측 수집의 비용이 크고, 새로 만드는 무료 오픈소스 제품에서 동일성 주장을 하지 않는 선택이 가능하다.
- 영향: 요구사항 SQ-V01(예측과 관측 기준선)은 예측 기준선만 필수로 한다. SQ-M04의 "알려진 기존 제품 결함의 재현/수정" 선택은 분석 근거로만 한다.
