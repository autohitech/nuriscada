# 고품질 SCADA 구현 요구사항 (초안)

> 상태: **초안 — 사용자 확인 전**. 새 구현이 갖출 품질 요구를 정리한다. 기존 제품 동작에서 온 요구는 근거를 달았고, 업계 관행에서 온 요구는 **[I] 제안**으로 표시했다. 표준 이름은 후보이며, 적용 여부와 범위는 사용자가 정한다. 표시는 근거 규약을 따른다. 우선순위: P0 = 1단계 필수, P1 = 1단계 목표, P2 = 후속.

## 0. 범위와 원칙

- **동작 동등성과 화면 자유를 분리한다.** 값, 알람, 통신, 파일처럼 관찰 가능한 동작은 원본과 맞춘다(Q-W4, 기준선). 화면의 모양과 상호작용은 새로 설계한다.
- **정보 구조와 용어는 유지한다.** 태그 편집기, 통신 포트 설정, 그래픽 편집기, 런타임 화면의 구성은 기존 사용자가 알아볼 수 있게 한다. 외형만 현대화한다.
- 경성 실시간 제어 루프는 지원 목표가 아니다(결정 0005). 제어는 PLC가 맡는다.
- 근거가 없는 요구는 근거를 만들 때까지 P2 이하로 둔다.

## 12. 확인이 필요한 것

- 대상 산업과 규모: 태그 수, 화면 수, 동시 클라이언트, 요구 스캔 주기.
- 사용 환경: 현장 터치 패널과 사무실 데스크톱의 비중.
- 적용할 표준(ISA-101, ISA-18.2, IEC 62443 등)의 필요 여부.
- 디자인 방향(차분한 산업용, 모던 대시보드, 일반 앱 느낌)과 참고 제품.
- 원본의 요소 단위 SVG 동적 속성 지원 여부(분석 미완료).
