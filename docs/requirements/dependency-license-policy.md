# 의존성·라이선스 정책 (초안)

> 상태: **초안 — 사용자 확인 전**. 새 구현이 어떤 의존성을 쓸 수 있는지, 어떻게 기록하고 검사하는지 정한다. 법률 검토가 아니다. 허용 범위가 불확실한 항목은 법무 확인 항목으로 남긴다. 표시는 근거 규약을 따른다.

## 1. 전제

- **공급사 EULA는 없다** (출처: 사용자, 2026-10-18). 설치 파일에서도 제품 EULA 파일을 찾지 못했다 O, [기록]. 따라서 새 구현은 **원본에서 가져오는 것이 없는 처음부터의 구현**으로 설계한다.
- EULA가 없다는 사실은 원본 코드·자산을 복사해도 된다는 뜻이 아니다 [I]. 저작권은 계약서 유무와 별개로 존재하므로 복사 금지를 유지한다. 이 판단의 법적 근거는 확인하지 않았다 [U].
- **새 프로그램의 이름은 NuriScada다. 새로 만들어 무료로 제공하고, 소스코드를 공개하며, 상업적 사용을 허용하고, 개발자는 문제 발생 시 법적 책임을 지지 않는 조건으로 낸다** (출처: 사용자, 2026-10-18). 기존 제품의 이름은 새 제품에서 쓰지 않는다. 이 문서의 "원본 제품"은 분석·호환 대상인 기존 제품을 가리킨다.
- 프로젝트 라이선스는 **Apache-2.0**으로 확정했다 (출처: 사용자, 2026-10-18; [결정 기록](../decisions/0001-license-apache-2.0.md)). 허용형이므로 GPL·AGPL 의존성은 링크할 수 없다 (§3).
- 무료로 배포해도 의존성의 라이선스 의무(GPL의 소스 공개, 고지 유지 등)는 가격과 무관하게 배포 행위에 적용된다 [I]. 그래서 등급표는 무료 제공이라고 완화하지 않는다.

| ID | 원칙 |

## 3. 라이선스 등급 (제안)

| 등급 | 라이선스 예 | 사용 | 조건 |
|---|---|---|---|
| A 허용 | MIT, BSD-2/3, Apache-2.0, ISC, Zlib, Unlicense/CC0, Ms-PL | 자유롭게 | 저작권·고지 유지. Apache-2.0은 NOTICE 파일 포함. Ms-PL은 소스 형태 재배포 시 조건 확인 |
| B 조건부 | MPL-2.0, EPL-2.0, LGPL | 수정하지 않는 의존성으로 사용. 동적 링크나 별도 구성 요소로 분리 | 해당 파일의 수정분 공개 의무, LGPL은 교체 가능성(동적 링크) 보장. 검토 필요 |
| C 금지(링크 불가) | GPL-2.0/3.0, AGPL, SSPL, 소스 공개를 요구하는 모든 라이선스 | 코어·배포물에 링크하거나 동봉하지 않는다 | 별도 프로세스·사용자 설치 방식도 법무 확인 전에는 쓰지 않는다 |
| D 불가 | 라이선스 불명, 비상업 한정, "보기 전용", 재배포 금지 | 쓰지 않는다 | 무료 제공이라도 비상업 조항은 산업 현장의 상업적 사용자에게 걸릴 수 있어 금지한다 [I] |

- 프로젝트 자체 라이선스가 GPL 계열로 정해지면 C 등급이 B로 바뀔 수 있다 [I]. 그 결정 전에는 위 표를 따른다.
- 이중 라이선스는 허용 쪽 하나를 선택하고 기록한다.

### 3-1. 프로젝트 자체 라이선스 (확정: Apache-2.0)

| 후보 | 상업적 사용 | 소스 공개 | 책임 제한 | 특징 |
|---|---|---|---|---|
| **Apache-2.0 (확정)** | 허용 | 사용자가 공개할 의무 없음 (우리는 공개) | 보증·책임 부인 조항 있음 | **특허 사용권 명시**와 기여자 특허 조항이 있다. 기여를 받는 오픈소스에 널리 쓰인다. NOTICE 파일 유지 |
| MIT | 허용 | 같음 | 보증·책임 부인 조항 있음 | 가장 짧고 단순. 특허 조항이 없다 |
| GPL/AGPL | 허용 | 파생물도 공개해야 함 | 같음 | 상업적 사용은 되지만 사용자가 비공개 제품에 넣기 어렵다. "상업적으로 사용해도 된다"는 취지와 맞는지 확인 필요 |

- 이유: 상업적 사용 허용과 무조건적인 책임 부인을 모두 원하셨으므로, 가장 널리 쓰이고 해석 선례가 많은 허용형을 권한다 [I].
- **허용형을 고르면 GPL·AGPL 의존성은 링크할 수 없다** (C 등급 유지). LGPL·MPL은 B 등급 조건을 지키면 가능하다.
- **책임 제한의 한계**: 라이선스의 "책임 없음" 문구는 표준이지만, 고의·중과실이나 인명 피해, 소비자 보호법 등 강행 규정에 따른 책임까지 계약으로 없앨 수는 없는 나라가 많다 [I]. 한국 법에서의 효력은 확인하지 않았다 [U]. 그래서 라이선스 문구에 더해 **안전 고지(DL-8)**, 문서의 사용 범위 명시, 안전 기능에 쓰지 말라는 경고를 같이 둔다. 법무 확인을 권한다.

## 5. 의존성 추가 절차

1. 후보의 라이선스, 유지보수 상태, 보안 이력, 전이 의존성을 확인한다.
2. 등급 A는 자동 통과한다. B는 사용 방식(수정 여부, 링크 방식)을 PR에 적고 검토를 받는다. C와 D는 금지다.
3. 의존성을 추가하는 PR은 검사 도구 통과와 SBOM 갱신을 포함해야 한다.
4. 글꼴·아이콘·이미지·SVG 심볼은 파일마다 출처와 라이선스를 `assets` 목록(출처 파일)에 적는다. 자체 제작 자산은 프로젝트 라이선스를 따른다고 적는다.
5. 의존성 제거·교체 시 고지 파일에서도 뺀다.

## 6. 자동화 (스택 결정 뒤 구체화)

| 항목 | 방법 |
|---|---|
| 라이선스 검사 | 스택별 도구를 CI에 둔다. 예: Rust는 `cargo-deny`, JavaScript/TypeScript는 라이선스 검사기, .NET은 라이선스 점검 도구. 허용·금지 목록은 저장소의 설정 파일로 관리한다 |
| SBOM | CycloneDX 또는 SPDX 형식을 배포물과 함께 낸다 |
| 고지 파일 | 의존성의 고지를 자동 모아 `THIRD_PARTY_NOTICES`를 만든다. 설치기·앱 안의 "정보" 화면에서 볼 수 있게 한다 |
| 취약점 | 의존성 취약점 점검(예: 해당 언어의 감사 도구)을 정기 CI에 넣는다 |
| 이력 | 고지·SBOM의 변경을 릴리스마다 보존한다 |

위 도구 이름은 예시이며, 선택은 기술 스택을 정한 뒤 한다.

## 7. 프로토콜·파일 형식·상표

- **프로토콜 구현**: 공개 규격(예: MODBUS), 공급사 공개 문서, 장치 시뮬레이터와의 상호 관측에서 출발한다. 원본 코드나 상수표를 옮기지 않는다 (DL-6). 프레임 분석은 규격과 관측으로 쓴다.
- **원본 파일 형식 읽기**: 호환을 위한 형식 구현이다. 형식 설명은 이 저장소의 분석 문서에서 출발한다. 원본 샘플 프로젝트를 저장소에 넣을 때는 출처와 제공 가능 여부를 먼저 확인한다 [U].
- **제품명·상표**: PLC 제조사 이름(MELSEC, S7 등)은 지원 장치를 설명하는 데만 쓰고 로고·상표를 쓰지 않는다. "원본 제품" 이름과 로고는 새 제품에 쓰지 않는다 [I]. 이름 결정은 별도다.

## 8. 기존 제품 분석 자료의 취급

- 기존 제품의 분석 자료(디컴파일 소스 포함)는 이 저장소에 두지 않는다. 별도의 비공개 저장소에서 읽기 전용으로 관리하며, NuriScada 코드는 그 자료를 import·복사·빌드 의존하지 않는다. 동작 명세는 분석자가 쓴 문서와 시험 기준으로 옮긴다.

## 8-1. 무료 제공에 따른 추가 요구 [제안]

산업 제어 소프트웨어를 무료로 배포하는 경우에 필요한 것이다. 법률 자문이 아니다.

| ID | 요구 |
|---|---|
| DL-7 | 배포물과 문서에 **보증 부인·책임 제한** 문구를 둔다 (선택한 프로젝트 라이선스의 표준 문구 사용). 설치 시 사용자에게 보여준다 |
| DL-8 | **안전 고지**: 이 소프트웨어는 인명·설비 안전을 보장하는 용도(비상 정지, 안전 계전기 대체)로 단독 사용하면 안 된다는 문구를 문서와 첫 실행 화면에 둔다 |
| DL-9 | 지원 범위(지원 OS, 지원 장치, 보안 업데이트 기간)를 문서에 명시한다. 무료 제공이라도 보안 패치 정책(취약점 신고 창구, 대응 기간)을 정한다 |
| DL-10 | 제품 이름은 **NuriScada**를 쓴다. "원본 제품"와 원본 로고는 쓰지 않는다. NuriScada 이름의 상표·충돌 여부는 확인하지 않았다 [U]. 저장소, 패키지, 도메인, 상표 등록을 정하기 전에 검색해야 한다 |
| DL-11 | 텔레메트리·자동 업데이트를 넣는다면 사용자에게 알리고 끌 수 있게 한다 |
| DL-12 | 기여를 받는다면 기여자 라이선스 동의(DCO 또는 CLA) 방식을 정한다 |

## 9. 확인이 필요한 것 [U]

| 항목 | 방법 |
|---|---|
| NuriScada 이름의 상표·이름 충돌 | 상표 데이터베이스와 패키지 저장소 검색 |
| 책임 제한 문구의 법적 효력(한국 및 배포 대상 국가) | 법무 확인 |
| 배포 형태 (소스 공개 여부, 설치형/SaaS) | 사용자 결정. AGPL·네트워크 조항 해석에 영향 |
| OPC Foundation, Fizzler, OpenSSL(옛 버전), WinIo, 키락 DLL의 라이선스 | 해당 배포처 문서 확인. 새 구현이 쓰지 않으므로 우선순위는 낮다 |
| 원본 형식의 호환 구현에 대한 법적 위험 | 법무 확인 |
| 영상 오브젝트를 브라우저 기능으로 구현할 때의 코덱 라이선스 | 코덱·컨테이너 지원 범위를 정한 뒤 확인 |
