# 설계 0003. 서버 API v1 (첫 수직 조각)

> 상태: 초기 구현. 운영 실행 파일은 계정·세션 인증을 요구하며, 인증 없는 읽기 전용 시연 라우터와 구분한다. 시간은 UTC 밀리초(1970년부터)다. 계정·로컬 쓰기·알람 이력의 조건과 한계는 [설계 0005](0005-operational-path.md)에 있다.

## 접속 제한 (SQ-S06)

- 기본 바인딩은 루프백(`127.0.0.1`)이다. 루프백이 아닌 주소는 `--allow-external`을 명시해야 하며 이 버전에는 인증이 없다.
- 루프백 바인딩에서는 `Host` 헤더의 호스트 이름이 `localhost`, `127.0.0.1`, `[::1]` 중 하나가 아니면 403이다. `Origin`이 있으면 같은 규칙으로 검사한다(DNS 재바인딩과 다른 웹 페이지의 접근 방어).

## 경로

| 경로 | 응답 |
|---|---|
| `GET /api/v1/tags` | `{ "tags": [TagSnapshot] }` |
| `GET /api/v1/screens` | `{ "screens": [ScreenSpec] }` |
| `GET /api/v1/alarms` | `{ "active": [TagSnapshot], "recent": [AlarmRecord] }` |
| `GET /api/v1/status` | `{ "version", "uptime_s", "tag_count", "devices": [DeviceStatus] }` |
| `WS /api/v1/stream` | 연결 직후 `{ "type": "snapshot", "data": { "seq", "tags", "active", "recent" } }`, 이후 `tags`와 `alarms` 묶음 프레임 |

- 수신이 느려 업데이트를 놓치면 서버가 전체 스냅샷을 다시 보낸다.
- 스냅샷보다 먼저 구독하므로 연결 직후의 변경을 놓치지 않는다.

### 웹소켓 묶음 형식 [O]

구현 근거: `crates/scheduler/src/wire.rs`, `crates/server/src/lib.rs`.

- 태그: `{ "type": "tags", "data": { "seq": 7, "time_ms": 1000, "items": [[3, 12.5, 1, "HIGH"], [9, true, 0, null]] } }`.
- `items`의 각 항목은 `[index, value, quality, alarm_state]`다. `index`는 현재 연결의 스냅샷 `tags` 배열에서 0부터 센 위치다. `quality`는 1(`good`) 또는 0(`bad`)이며 값과 알람 상태는 `null`일 수 있다. 이름·장치·단위는 스냅샷에서 가져온다.
- `time_ms`는 묶음을 만든 UTC 밀리초다. 웹 클라이언트는 이 값을 변경 항목의 `changed_ms`로 쓴다. 스냅샷의 `changed_ms`는 허브에서 실제 변경을 기록한 시각이다.
- 태그 묶음 `seq`는 1부터 증가한다. 서버는 스냅샷 `seq` 이하인 대기 묶음을 버린다. 재접속·재동기화 때는 새 스냅샷으로 목록과 기준 순번을 교체한다.
- 알람: `{ "type": "alarms", "data": [AlarmRecord, ...] }`. 알람 기록의 `seq`는 태그 묶음 순번과 별개다. 스냅샷과 겹칠 수 있으므로 클라이언트는 마지막으로 본 알람 순번 이하의 기록을 버린다.
- 방송 간격은 프로젝트의 `publish_ms`로 설정하며 기본값은 100 ms다. 같은 태그가 간격 안에서 여러 번 바뀌면 마지막 상태만 묶는다. 알람 기록은 별도로 묶어 보낸다. 최근 기록 1000개를 넘어 밀려난 알람은 복구하지 못한다.

## 형식

**TagSnapshot**: `name`, `device`, `kind`(`analog`/`digital`), `value`(숫자, 불리언, 또는 읽은 적 없으면 `null`), `quality`(`good`/`bad`), `changed_ms`(값·품질·알람 상태가 마지막으로 바뀐 시각, 읽은 적 없으면 0), `unit_text`, `alarm_state`(`NORMAL`/`LOLO`/`LOW`/`HIGH`/`HIHI`/`MIDDLE` 또는 알람이 없으면 `null`).

**AlarmRecord**: `seq`(1부터 순서 보장), `time_ms`, `tag`, `event`(`HIHI`, `HIGH`, `LOW`, `LOLO`, `CNF`, `RETURN`, `DI_ON`, `DI_OFF`), `value`(발생 시점의 값, 디지털은 0 또는 1).

**DeviceStatus**: `name`, `connected`, `round_trip_ms`, `requests_ok`, `requests_failed`, `scan_ms`, `scans`, `overruns`(계획 시각을 놓친 스캔 수), `jitter_p99_us`(최근 표본의 99번째 백분위수), `jitter_max_us`(전체 기간 최댓값), `last_error`.

## 동작 규칙

- 읽기에 실패하면 해당 블록의 태그는 품질이 `bad`가 되고 **마지막 값은 유지**한다. 성공하면 `good`으로 돌아온다.
- 범위 처리로 값이 버려진 경우 이전 값을 유지하고 품질은 `good`이다.
- 값·품질·알람 상태가 바뀌지 않으면 방송하지 않는다.
- 허브에는 최근 알람 1000개를 메모리에 둔다. 운영 서버는 별도 SQLite 이력과 확인 정보를 보관한다.

## 한계 (슬라이스)

- 활성 알람 목록은 아날로그 알람 상태가 정상이 아닌 태그만 포함한다. 디지털 알람은 기록(`recent`)에만 나타난다.
- 운영 API는 아래 확장을 사용한다. 읽기 전용 시연 서버에는 조작 저장소가 없다.
- 타입 생성(TypeScript)은 웹 프레임워크 결정 뒤에 정한다.

## 운영 경로 확장 [O]

| 경로 | 의미 |
|---|---|
| GET /api/v1/auth/session | 인증 필요 여부·현재 사용자·만료·쓰기 및 로컬 관리 가능 여부 |
| POST /api/v1/auth/login | username·password 검증 후 HttpOnly 쿠키 발급 |
| POST /api/v1/auth/logout | 세션 폐기 |
| POST /api/v1/users | 관리자 계정 추가: username·password·role |
| GET /api/v1/audit?after=N | 관리자 감사 조회, 오름차순 최대 200개 |
| GET /api/v1/control/tags | 쓰기를 허용한 태그의 name·kind(bool/word) |
| POST /api/v1/control/tags/{name} | value 원시 값 쓰기. 장치 응답 확인을 반환하며 자동 재시도하지 않음 |
| GET /api/v1/project | 관리자 프로젝트 설정(장치·태그·서버 명세) 및 표준 TOML 조회 |
| POST /api/v1/project | 로컬 관리자 프로젝트 설정 검증·원자적 TOML 저장·스캐너 및 허브 즉시 재적용 |
| GET /api/v1/history/alarms?before=N&tag=이름 | 최신순 알람 이력 최대 200개. before=0은 첫 페이지, tag는 선택 |
| POST /api/v1/history/alarms/{id}/ack | 발생 건 확인. 정상 복귀와 별개 |
| GET /api/v1/history/tags?tag=이름&from_ms=N&to_ms=M&limit=K&format=json\|csv | 태그 시계열 값 이력 조회(오름차순 최대 2000개) 및 CSV 내려받기 |

로그인·세션 상태 외 운영 API는 세션 쿠키가 필요하다. 모든 POST에는 X-NuriScada-Request: 1 헤더와 JSON 본문을 사용한다. 일반 운영 API의 입력 크기는 최대 4096바이트이며, `/api/v1/project`는 최대 256 KiB다. 역할·접속 경로·공개 모드는 서버가 검사하며 상세 조건은 설계 0005를 따른다.
