# 설계 0007. 쓰기 큐 정책: 재시도·병합·다중 쓰기·인터록

> 상태: **확정 — 결정 0016.** 단일 쓰기 직렬화·묶음 쓰기 API(#46)는 구현됐다 [O]. 재시도 없음·묶음 미합병은 현행 유지로 확정하고, 인터록·기존 명령 0·100은 보류한다([결정 0016](../decisions/0016-write-queue-policy.md)). 표시: [O] 관측/확정, [I] 추론/제안, [U] 미확인. 요구사항 [SQ-R04](../requirements/scada-quality-requirements.md), 설계 [0005](0005-operational-path.md)의 쓰기 경로를 따른다. 기존 제품 코드는 반입하지 않았으며, 참조 저장소의 관측 기록은 읽기 전용으로만 봤다.

## 1. 현재 동작 [O]

- 쓰기 요청은 세마포어 16개 안에서 받고(`WriteQueueFull`이면 429), 뮤텍스 하나로 한 번에 하나씩 장치에 보낸다. 실행 중·대기 중 요청은 합쳐서 16개까지다.
- 드라이버는 단일 쓰기와 묶음 쓰기(MODBUS 15·16, MELSEC 1401 다점)를 보낸다. 요청을 보낸 뒤 응답이 늦거나 끊기면 **자동 재시도하지 않는다**(이중 동작 방지).
- 결과와 무관하게 `write.request`(대기)·`write.result`(수락·실패)·`write.denied`(거부)를 감사에 남긴다. 비밀번호·세션 토큰은 넣지 않는다.

## 2. 재시도 정책 [I: 제안]

- 요청 바이트를 보내기 **전**에 실패(연결 실패)한 경우에만 1회 다시 연결해 보낸다. 이미 보낸 요청의 응답 유실·시간 초과는 재시도하지 않는다 [I]. 이유: 장치가 이미 반영했을 수 있어 재전송이 이중 동작이 된다.
- 재시도·포기·장치 오류는 모두 `write.result`에 남기고, 다음 스캔이 실제값을 덮어써 확인한다(현재 E2E 방식 유지).

## 3. 병합 정책 [I: 제안]

- 대기열에 같은 태그의 쓰기가 여러 개 있으면 **최종값 하나만** 장치에 보낸다(last-wins). 중간값은 버리되 `write.request` 기록은 남긴다 [I]. 이유: 고속 조작(슬라이더·연타)이 장치를 밀어내지 않게 한다.
- 서로 다른 태그는 순서를 바꾸지 않는다.

## 4. 다중 쓰기 [U: 후속]

- 연속 주소의 묶음은 드라이버 배치 기능으로 한 번에 보낸다(MODBUS 15·16이 첫 후보). 배치는 원자 취급한다: 부분 실패 시 남은 점의 자동 분할 재시도는 하지 않고 전체 실패로 보고한다 [I].
- 순서: MODBUS 배치 → 스케줄러 묶음 계획 → 나머지 드라이버 배치. 현행 단일 쓰기는 그대로 둔다.

## 5. 제어 인터록 [I: 요구사항 초안 있음, 사용자 확인 대기]

- 요구사항 SQ-C07·SQ-C08(운전 인터록, 안전 기능 아님)을 제안으로 적었다. 조건식 문법·검사 시점(장치 전송 전)·거부 감사 형태는 요구사항을 따른다. 사용자가 확정하면 설계·구현한다.

## 6. 기존 명령 대응 [U]

- 참조 저장소의 정적 관측에 따르면 command 1은 단일 쓰기 분배기, command 2는 블록 쓰기이며 자동 워드 폴백 루프는 관측되지 않았다 [I: 읽기 전용 참조]. command 0·100의 의미는 미확인이다 [U].
- 그래서 command 1≈단일 쓰기·command 2≈배치 쓰기로만 대응한다. 값 정밀도는 설계상 차이가 없다:
  5종 드라이버의 쓰기는 모두 원시 정수(`u16`)만 받고, 서버는 소수·범위 밖 값을 반올림하지 않고
  `write.bad_value`로 거부한다(시험 `실수가_섞인_쓰기는_반올림하지_않고_거부한다`). command 0·100 매핑은 보류한다([O] 정밀도, [U] 0·100).

## 7. 검증 계획

- 시뮬레이터의 연결 끊기·응답 지연·범위 밖 오류 주입으로 재시도 금지·항목 오류·감사 기록을 시험한다(현행 시험 방식 확장).
- 병합·다중 쓰기는 구현 PR에서 묶음 E2E(요청 N건→장치 전송 1건→감사 N건)로 확인한다.
