# 설계 0005. 계정·로컬 쓰기·알람 기록의 첫 운영 경로

> 상태: 초기 구현 [O]. 현장 배포 완료나 보안 인증을 의미하지 않는다. 2026-10-18 사용자의 당일 구현 목표에 맞춰 조작의 선행 조건과 데이터 보존부터 구현한다.

## 계정과 접근

- [O] 기본 계정·비밀번호는 없다. 최초 관리자는 로컬 CLI에서 비어 있는 DB에 한 번만 만든다. 비밀번호는 12~128 UTF-8 바이트, 계정 이름은 영문·숫자·밑줄·하이픈·점 1~64자다.
- [O] Argon2id 기본 매개변수로 비밀번호를 해시하고 OS 난수로 솔트를 만든다. 세션은 256비트 난수이며 DB에는 SHA-256 해시만 저장한다. HttpOnly·SameSite=Strict 쿠키, 8시간 절대 만료, 사용자당 최신 세션 하나를 사용한다. 로그아웃은 세션을 폐기하며 웹소켓도 30초마다 만료·폐기를 확인한다.
- [O] 서비스 전체에서 60초당 자격증명 검증 10회, 동시 비밀번호 연산 2개로 제한한다. 계정 존재 여부와 무관한 실패 메시지와 해시 검증을 사용한다.
- [O] 관리자(admin)는 계정 추가·감사 조회·조작, 운전원(operator)은 조작, 조회자(viewer)는 읽기를 할 수 있다. 화면·태그별 세부 권한, 계정 비활성화·비밀번호 변경·복구, OIDC/LDAP은 아직 없다.
- [O] 변경 API는 X-NuriScada-Request: 1 헤더가 필요하다. Origin이 있으면 Host의 정확한 출처와 일치해야 한다. 교차 출처 CORS는 허용하지 않고 API 응답은 no-store다.

## 쓰기 경로

최초 관리자 설정 → 로그인 → 역할 검사 → 쓰기 내용 확인 → MODBUS 장치 응답 → 다음 스캔 값 표시 → 감사 조회.

- [O] 서버의 --enable-writes, 루프백 바인딩, 실제 TCP 출처의 루프백, 태그의 writable=true가 모두 필요하다. 기본은 비활성이다. 프록시 헤더로 권한을 올리지 않는다. 코일·보유 레지스터와 유닛 1 이상만 허용한다.
- [O] 코일은 JSON true/false, 레지스터는 환산 전 원시 정수 0~65535다. 역환산은 하지 않는다. 품질이 bad인 태그에는 쓰지 않는다. 웹 화면에서 대상·값을 확인한 뒤 별도 버튼으로 전송한다.
- [O] 실행 중·대기 중 요청은 인스턴스 전체 16개까지이며 하나씩 직렬 실행한다. 큐 진입 뒤에도 세션을 확인한다. MODBUS 단일 코일(05)·단일 레지스터(06)만 지원한다.
- [O] 장치 전송 전에 이전 표시값·요청 원시값을 감사 DB에 커밋한다. 저장 실패 시 전송하지 않는다. 응답 뒤 결과를 별도로 기록한다. 장치 조작과 DB 저장은 원자적 트랜잭션이 아니므로 요청만 남으면 결과 미확인으로 조사한다.
- [O] 응답이 없으면 장치가 이미 썼을 가능성이 있어 자동 재시도하지 않는다. 성공은 응답의 거래·유닛·기능·주소·값 일치이며 물리적 동작 완료가 아니다. 표시값은 다음 정상 스캔으로 확인한다.
- [U] 기존 쓰기 명령 0/1/2/100, 큐 병합·재시도 정책, 다중 쓰기, 제어 인터록, LAN/VPN 제어 경로는 후속이다.

## 공개 구성

- [O] 공개 배치는 --public-read-only를 반드시 사용한다. 루프백 뒤의 역방향 프록시에도 적용되며 로그인·로그아웃 외의 모든 변경 API를 서버에서 거부한다. 비루프백 바인딩도 조작·계정 변경을 거부한다.
- [O] 명시적 공개 모드에서는 공개 Host와 같은 Origin을 허용하고 루프백 뒤에서도 Secure 세션 쿠키를 사용한다. 일반 로컬 모드의 localhost·루프백 Host 제한은 유지한다.
- [O] 서버가 인터넷 공개 여부를 자동 판별하지는 않는다. 공개 프록시를 로컬 쓰기 인스턴스에 연결하면 안 된다. 비루프백 세션 쿠키에는 Secure를 붙인다. 서버 자체 TLS가 없으므로 외부 접속은 HTTPS 프록시가 필요하다. 최종 보안 검토는 아직 하지 않았다 [U].

## 저장·알람 확인

- [O] SQLite(WAL, synchronous=FULL)에 계정·세션·감사·알람·확인 정보를 저장한다. 데이터는 웹 자원 경로 밖에 둔다. Unix 데이터 디렉터리는 0700이어야 하며 새 디렉터리는 자동 설정한다. Windows ACL은 설치·운영 설정에서 제한해야 한다.
- [O] 프로젝트마다 별도 데이터 디렉터리를 사용한다. 온라인 백업·스키마 마이그레이션 도구는 아직 없다. 백업은 WAL까지 일관성을 보장해야 한다.
- [O] 알람은 200 ms마다 DB로 옮긴다. 실행 식별자와 허브 순번으로 중복을 막고 DB id로 재시작 후에도 조회한다. 최신순 200개 페이지와 태그 필터를 지원한다.
- [O] 운전원·관리자는 로컬에서 발생 건별로 ACK한다. 행위자·시각과 감사 기록을 같은 트랜잭션에 저장한다. 중복 ACK는 변경하지 않는다. ACK와 정상 복귀는 별개며 CNF·RETURN 기록 자체에는 ACK하지 않는다.
- [O] 저장 실패·최근 1000개 링 버퍼를 넘긴 손실은 진단 상태와 화면의 알람 기록 오류로 드러낸다.
- [O] 태그 시계열 값 이력(`tag_history`)은 200 ms 주기 보관 작업에서 값·품질·알람 상태가 바뀌었거나 마지막 저장 뒤 5초가 지난 태그 표본을 SQLite에 함께 저장한다. 태그당 최신 10,000개 표본을 유지하며 오래된 표본은 자동 정리한다.
- [O] 로그인한 모든 역할(`viewer`·`operator`·`admin`)은 `GET /api/v1/history/tags`로 태그별 시계열 표본(JSON, 시간 오름차순 최대 2,000개)을 조회해 웹 SVG 트렌드 그래프·최소/최대/최신 통계로 확인하고, `format=csv`로 RFC 4180 호환 CSV 파일을 내려받을 수 있다.
- [U] 비정상 종료 직전 미저장 약 200 ms와 DB 대기 시간의 알람·값 표본은 잃을 수 있다. 디스크 장애 복구·장기 외부 아카이브·무손실 보장은 아직 없다. 기록 오류 상태는 현재 실행의 진단이며 재시작 간 오류 이력은 후속이다.

## 프로젝트·태그·통신 설정 편집

- [O] 로컬 관리자(admin)는 `GET /api/v1/project`와 `POST /api/v1/project` 및 웹 편집 화면에서 TOML 파일을 직접 열지 않고 통신 장치(`modbus-tcp`)와 태그(아날로그/디지털, 환산, 알람, 쓰기 허용 여부)를 추가·수정·삭제할 수 있다.
- [O] 서버는 입력 명세를 `Project::from_spec`으로 먼저 검증해 중복 이름, 없는 장치, 잘못된 영역·알람 한계, 비유한 실수(NaN/Inf)를 거부한다. 검증에 실패하면 기존 파일과 실행 중인 스캐너는 바뀌지 않는다.
- [O] 검증을 통과하면 기존 설정을 `.toml.bak`으로 복사한 뒤 임시 파일 기록·`sync_all`·원자적 `rename`으로 설정 파일을 교체한다. 이어서 감사 기록(`project.update`)을 남기고, 기존 스캐너를 정리한 뒤 `Hub::reconfigure`로 새 전체 스냅샷을 웹소켓 수신자들에게 방송하고 새 스캐너를 시작한다.
- [U] 서버 수신 주소(`server.listen`) 변경은 파일에 저장되지만 현재 열려 있는 TCP 소켓 재바인딩은 서버 재시작 시 반영된다. 다중 파일 분할·버전 간 비교·롤백 UI는 후속이다.

## 그래픽 공정 화면 런타임과 편집기

- [O] 프로젝트 설정은 선택적 `[[screen]]` 및 `[[screen.widget]]` 블록을 지원하며 `GET /api/v1/screens`로 모든 인증된 사용자에게 제공된다.
- [O] 각 위젯은 외부 스크립트나 임의 HTML 없이 구조화된 벡터 심볼(`tank`, `gauge`, `pump`, `valve`, `lamp`, `value`, `label`)로만 렌더링된다(SQ-G01, SQ-G04, SQ-G10). 태그의 실시간 값·단위·알람 상태·통신 품질(`bad` 점선 테두리 및 상태 배지)이 변경분만 반응형으로 반영된다(SQ-G07).
- [O] 로컬 관리자(`admin`)는 웹 그래픽 편집 모드에서 10 px 격자 스냅, 드래그 이동, 위젯 추가·삭제·태그 연결·속성 편집, 태그 자동 배치를 수행하고 `POST /api/v1/project`로 저장해 즉시 반영할 수 있다(SQ-G08).
- [U] 기존 제품의 화면 파일(MODX) 직접 가져오기와 약 120종 전체 오브젝트 및 그룹·레이어·실행 취소는 후속 조각이다.

## 감사 기록의 범위

- [O] 자격증명 검증을 수행한 로그인 성공·실패, 로그아웃, 계정 생성, 프로젝트 설정 변경(`project.update`), 쓰기 거부·요청·결과, ACK를 기록한다. 비밀번호·세션 토큰은 넣지 않는다. 속도·동시 처리 제한에서 거부한 모든 HTTP 요청을 개별 저장하지는 않는다.
- [O] 순서 번호·이전 해시·JSON 사건의 SHA-256 체인으로 시작 시·조회 시 검사한다. 변경·삭제 API는 없다.
- [U] DB 관리자에 의한 전체 체인 재작성·끝부분 삭제는 외부 앵커 없이 검출하지 못한다. 외부 서명·원격 보관·보존 정책은 후속이다.

## 실행

    cargo run -p nuriscada-server -- --config examples/demo.toml --init-admin admin
    cargo run -p nuriscada-sim-modbus -- --demo
    cargo run -p nuriscada-server -- --config examples/demo.toml --enable-writes

첫 명령은 비밀번호를 숨김 입력받고 설정 후 종료한다. 자동화에는 --password-stdin을 사용하고 비밀번호를 명령행 인자로 넣지 않는다. --data-dir를 바꾸면 초기 설정과 실행에 같은 경로를 준다. 기본은 설정 파일 옆 .nuriscada다.

시험·부하 도구의 router/router_with_web은 인증 없는 읽기 전용 시연 서버로 유지한다. 운영 실행 파일과 구분하며 현장 운영 서버로 사용하지 않는다.

## 구현 근거와 검증

- [Argon2 0.5.3](https://docs.rs/argon2/0.5.3/argon2/), [getrandom OS 난수](https://docs.rs/getrandom/0.3.4/getrandom/fn.fill.html), [rusqlite 0.40.2](https://docs.rs/rusqlite/0.40.2/rusqlite/)
- [MODBUS 공개 응용 규격](https://www.modbus.org/file/secure/modbusprotocolspecification.pdf) 기능 05·06
- [O] 새 의존성을 포함한 cargo-deny의 라이선스·취약점·출처 검사가 통과했다.
- [O] 시뮬레이터 실제 쓰기·잘못된 영역/값/유닛 거부·응답 유실 시 재전송하지 않음을 시험했다.
- [O] 인증·출처·확인 헤더·역할·기본 비활성·공개 바인딩의 쓰기 차단, 감사 조회 제한, 로그아웃·만료·로그인 속도 제한을 시험했다.
- [O] DB 재개방 후 계정·알람·ACK 보존, 감사 변조 감지, ACK가 활성 알람을 정상으로 만들지 않음을 시험했다.
- [O] 프로젝트 명세·TOML 왕복 변환, 비관리자·잘못된 설정 거부, 런타임 태그 추가 후 스캐너 재적용·즉시 읽기/쓰기·감사 기록(`project.update`)을 통합 시험과 Orca 브라우저에서 확인했다.
- [O] 태그 시계열 값 이력 저장, JSON 조회, CSV 내보내기(`Content-Type: text/csv; charset=utf-8`), 웹 SVG 트렌드 차트 표시를 통합 시험과 Orca 브라우저에서 확인했다.
- [O] 그래픽 화면(`[[screen]]`, `[[screen.widget]]`) 검증·TOML 직렬화, `GET /api/v1/screens` 조회, 웹 SVG 공정 화면 렌더링 및 편집·저장을 통합 시험과 Orca 브라우저에서 확인했다.
- [O] Orca 브라우저에서 최초 관리자 로그인 → 원시 레지스터 95 쓰기 → 표시값 95·상상한 알람 갱신 → 이력 ACK → 쓰기·ACK 감사 조회 → 로그아웃 후 값 화면 숨김을 확인했다. 확인에 사용한 시뮬레이터·서버는 종료했다.
- [U] 이 운영 경로의 기준 장비 성능·장기 시험과 실제 PLC 검증은 별도다. 진행 중인 S5 72시간 시험은 기존 바이너리를 유지한다.
- [O] 장기 시험과 같은 개발 기계에서 빌드·통합 시험도 진행하고 있다. 전용 장비에서 다른 작업을 배제한 측정과 구분해야 한다.

당일 후속 우선순위 제안 [I]: 기존 프로젝트 가져오기·추가 드라이버.
