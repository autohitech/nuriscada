# 설계 0006. 웹 UI 다국어

> 상태: 구현됨(한국어, 영어). 요구사항 SQ-U09(P0)의 첫 조각이다.

## 방식

- 화면 문자열은 `web/src/lib/locales/`의 언어별 사전에 모은다. 한국어(`ko.ts`)가 기준이고, 다른 언어는 같은 모양(`Messages`)을 따른다. 매개변수가 있는 문구는 함수다(`moreAlarms(n)`).
- `web/src/lib/i18n.svelte.ts`의 `m`이 **지금 언어의 문자열**이다(Svelte 반응형). 컴포넌트는 `m.login`처럼 읽고, 언어를 바꾸면 화면이 바로 바뀐다. 라벨 보조 함수 `stateLabel`, `eventLabel`은 모르는 값을 그대로 보여 준다.
- 언어 결정: 사용자가 상태 줄의 선택 상자로 고른 값(브라우저에 저장)이 있으면 그것, 없으면 브라우저 언어 목록의 첫 지원 언어, 둘 다 없으면 영어다(`detectLocale`). 선택하면 `<html lang>`도 바뀐다.
- 날짜·숫자는 현재 언어의 로캘로 표시한다(`formatDateTime`, `formatValue`). 시각(`HH:MM:SS`)은 24시간제로 통일한다.

## 시험

- 영어 사전의 키가 한국어와 **정확히 같은지**(중첩 포함), 함수 문구의 인자 수가 같은지, 영어에 한글이 섞이지 않았는지 검사한다. 새 키를 한국어에만 넣으면 시험이 실패한다.
- 언어 결정 규칙과 언어 전환을 시험한다.

## 언어 추가하는 법

1. `web/src/lib/locales/<코드>.ts`를 만들어 `Messages` 형식으로 모든 키를 채운다.
2. `i18n.svelte.ts`의 `Locale`, `LOCALES`, `LOCALE_NAMES`, `dictionaries`, `detectLocale`, `localeTag`에 추가한다.
3. `i18n.test.ts`의 지원 언어 시험을 갱신한다.

요구사항의 대상 언어(일본어, 중국어 간체, 베트남어)는 번역 검수자가 있을 때 추가한다.

## 한계

- **서버가 보내는 오류 메시지는 아직 한국어다.** 로그인 실패, 설정 검증 오류 같은 서버 문구가 화면에 그대로 나온다. 오류 코드를 보내 화면이 번역하도록 바꾸는 일이 후속이다.
- **사용자가 만든 내용은 번역하지 않는다**(태그 이름, 화면 이름, 위젯 표시 이름, 설명).
- 사용자 문서(`docs/user/`)는 한국어만 있다.
- 영어 번역은 개발자가 썼고 원어민 검수를 받지 않았다. 자연스럽지 않은 표현이 있을 수 있다.
- 오른쪽에서 왼쪽으로 쓰는 언어(RTL)는 지원하지 않는다.
